# 배드민턴 대진판 — 배포 안내

## 폴더 구조

```
.
├── firebase.json              Firebase Hosting 설정
├── firestore.rules            Firestore 보안 규칙 (따로 배포해야 합니다)
├── docs/
│   ├── requirements.md        확장·글로벌·유료화 요구사항 명세서
│   └── multi-club.md          여러 동호회 · 유료 멤버십 구조 설계
└── public/                    실제로 배포되는 폴더
    ├── index.html
    ├── manual.html            사용 설명서만 따로 여는 페이지 (링크 배포·인쇄용)
    ├── firebase-config.json   Firebase 연결 정보 (이미 채워져 있음)
    ├── css/
    │   └── app.css
    └── js/
        ├── firebase-loader.js  Firebase SDK 로딩 (모듈)
        ├── sound.js            효과음 (WebAudio 합성)
        ├── store.js            저장소 어댑터 (Firestore / 로컬)
        ├── state.js            설정 기본값, 상태, 세션 마감
        ├── secret.js           운영자 비밀번호 (해시·최초 설정·확인)
        ├── algo.js             자동 배치 알고리즘
        ├── manual.js           사용 설명서 본문 (도움말 탭·manual.html 공용)
        ├── ui.js               화면 그리기
        ├── actions.js          저장·되돌리기·이동/교체
        ├── auth.js             역할과 권한, 운영자 동시접속 제한
        ├── gate.js             첫 접속 입장 화면
        ├── interact.js         드래그앤드롭, 버튼 이벤트, 모달
        ├── screens.js          출석·회원·기록·설정·도움말 화면
        └── main.js             부팅, 실시간 동기화, 경기 알림
```

## 배포

압축을 푼 폴더에서:

```bash
firebase deploy --only hosting
```

프로젝트가 아직 연결되지 않았다면 한 번만:

```bash
firebase login
firebase use --add        # ohmycock 프로젝트 선택
firebase deploy --only hosting
```

## 파일을 고칠 때

**스크립트 로드 순서에 의존합니다.** `index.html`의 `<script>` 순서를 바꾸지 마세요.
고칠 부분만 해당 파일을 열면 됩니다.

| 하고 싶은 것 | 열어야 할 파일 |
|---|---|
| 배치 규칙, 가중치, 성별 정책 | `js/algo.js`(파일 첫 주석에 전체 그림), `js/state.js` |
| 화면 배치·색·글꼴 | `css/app.css` |
| 권한 규칙 | `js/auth.js` |
| 입장 화면 문구 | `js/gate.js` |
| 효과음 | `js/sound.js` |
| 사용 설명서 내용 | `js/manual.js` (도움말 탭과 `manual.html`이 함께 씁니다) |
| 운영자 비밀번호 | `js/secret.js` + `firestore.rules` (둘이 한 쌍입니다) |

## 배포가 반영됐는지 확인하는 법

**설정 → 버전 → 앱 버전**을 보세요. 현재 배포본은 `2026.08.14e` 입니다.
재배포했는데 이 숫자가 그대로면 브라우저가 옛 파일을 쓰고 있는 것입니다.
새로고침(모바일은 탭을 닫았다 다시 열기)하세요.

파일을 고쳐서 재배포할 때는 `js/state.js`의 `APP_VERSION`과
`index.html`의 `?v=` 값을 같이 올려 주세요. 캐시가 자동으로 갈립니다.

## 사용 설명서 (회원·운영자용)

앱 안 **도움말** 탭에 있습니다. 뷰어(게스트)에게도 보입니다 — 처음 온 사람이
제일 먼저 필요한 글이라 역할로 가리지 않았습니다.

같은 글을 앱 없이 볼 수 있는 주소도 있습니다.

```
https://<배포주소>/manual.html
```

단톡방에 링크로 붙이거나 인쇄해서 체육관에 붙여 두는 용도입니다. 인쇄용 CSS가
들어 있어 목차와 하단 링크는 종이에서 빠집니다.

**본문은 `js/manual.js` 한 곳에만 있습니다.** 도움말 탭과 `manual.html`이 이
파일을 함께 읽으므로 글을 고칠 때 한 군데만 고치면 됩니다. 설명서는 앱 상태
(`S`·`Auth`…)를 읽지 않습니다 — `manual.html`은 앱 스크립트를 아예 불러오지
않기 때문입니다. 그래서 코트 수나 회원 수처럼 클럽마다 다른 값은 적지 않고
"어디를 보면 되는지"만 안내합니다.

구성은 네 장입니다.

| 장 | 내용 |
|---|---|
| 1. 처음 들어가기 | 운영자 / 회원 / 게스트 중 고르기 |
| 2. 회원용 | 입장(이름 가리기), 출석, 내 차례, 화면 읽는 법, 내 권한 |
| 3. 운영자용 | 화면 구성, 더블탭·드래그, 시작과 종료, 순서 규칙, 회원 관리, 명단 보호, 마감 |
| 4. 잘 안 될 때 | 붉은 띠, 명단이 비어 보일 때, 버전 확인 등 |

도움말을 지금 역할로 열면 해당 장에 **지금 내 역할** 표시가 붙습니다. 다른 장도
막지 않고 그대로 보여 줍니다.

## 화면과 조작

### 배치

```
┌─────────────────────────────────────┐
│  코트  (가로로 나란히, 화면 위쪽)      │
├──────────────────┬──────────────────┤
│  대기열           │  대기 인원        │
└──────────────────┴──────────────────┘
```

폰에서는 좌우로 나누면 각각 반토막이 나므로 **코트 → 대기열 → 대기 인원**을
한 줄로 쌓고 화면 전체를 스크롤합니다.

### 밝은 바탕 · 색으로 구분하는 남녀 · 큰 이름

체육관 조명 아래에서는 어두운 화면이 반사 때문에 오히려 안 읽혀서 흰 바탕으로
바꿨습니다.

**남녀는 이름 색으로만 구분합니다** — 남색 파랑, 여성 자홍. ♂♀ 아이콘이나 배지는
없앴습니다. 흰 바탕 대비는 각각 약 6.3:1 / 5.9:1로, 20px 이상 굵은 글씨 기준
(AAA 4.5:1)을 넘습니다. 성별이 입력되지 않은 사람은 주황으로 눈에 띄게 둡니다.

이름은 굵기 900에 자리마다 크기를 달리합니다 — **코트 31px / 대기열 22px /
대기 인원 20px**, 폰에서는 25 / 15 / 18px입니다. 대기열은 네 명을 **한 줄**에
늘어놓습니다.

### 버튼 없이 — 더블탭과 드래그로만

**코트에는 버튼이 하나도 없습니다.** 시작·종료·빼기·잠금을 전부 없앴습니다.

- **4명이 차면 무조건 자동 시작**됩니다(손 배치·자동 배치·드래그·더블탭 무엇이든).
- **더블탭 = 다음 단계로.** 대기 인원 → 대기열 → 코트 → 대기 인원 순환입니다.
  이름을 두드리면 그 사람만, 팀 박스의 머리 부분을 두드리면 팀 전체가 갑니다.
  빈자리는 **언제나 앞에서부터** 채웁니다(Q1 → Q2 → …, 1코트 → 2코트 → …).
  대기열은 앞에서부터 나가는 줄이므로 순서가 흐트러지지 않게 선입선출로 고정했습니다.
- **드래그 = 어디로든.** 이름도 팀 박스도 코트·대기열·대기 인원 어디로든 끌 수
  있습니다. 4명이 안 되는 팀도, 진행 중인 코트도 됩니다.

| 두드린/끈 곳 | 이름 하나 | 팀 박스 |
|---|---|---|
| 대기 인원 | 대기열 빈자리로 | — |
| 대기열 | 빈 코트 자리로 | 팀 전체가 코트로 |
| 코트 | 대기 인원으로 | 팀 전체가 대기 인원으로 |

#### 경기는 어떻게 끝내나

**코트 팀을 대기 인원으로 보내면 그것이 곧 종료입니다.** 게임 수가 올라가고
기록에 남습니다(더블탭 또는 대기 인원 쪽으로 드래그).

반대로 **대기열이나 다른 코트로 옮기는 것은 종료가 아닙니다.** 경기를 하지 않은
것이므로 진행 중이던 기록을 지웁니다. 개인을 코트에서 빼내는 것도 마찬가지입니다.

한 줄로: **다음 단계(대기 인원)로 가면 종료, 옆으로 옮기면 무효.**

> 종료 확인창이 사라지면서 **리벤지(같은 멤버로 다시 대기 등록)** 선택지도 함께
> 없어졌습니다. 같은 팀으로 다시 붙이려면 대기 인원에서 네 명을 대기 슬롯으로
> 끌어다 놓으세요.

### 자동 배치 알고리즘

`js/algo.js` 첫 주석에 전체 그림이 있습니다. 요약하면:

```
대기 인원 ──충원──> 대기열 ──투입──> 코트 ──종료──> 대기 인원
```

`autoAssign()`은 **투입 → 당기기 → 충원** 세 단계를 변화가 멎을 때까지
되풀이합니다. 순서를 바꾸면 안 됩니다 — 충원이 먼저 돌면 Q1이 비는 즉시
방금 친 사람들로 다시 채워져 뒤 슬롯이 영영 앞으로 오지 못합니다.

> **순번 당기기는 자동 토글과 무관하게 항상 돕니다.** Q1이 비면 Q2가 그 자리로
> 올라옵니다 — 코트에 투입해서 비었든, 팀을 대기 인원으로 내려서 비었든,
> 한 명씩 빼내서 비었든 마찬가지입니다. 사람을 새로 *배정*하는 일이 아니라 줄의
> 빈칸을 메우는 일이라, `autoAssign()`이 아니라 모든 조작을 감싸는 `tx()`에
> 들어 있습니다. 그래서 **자동을 꺼도** 대기열에 빈 슬롯이 남지 않습니다.

누구를 뽑을지는 두 단계로 정합니다.

1. **개인 점수**로 후보를 추립니다 — 게임 수가 적고 오래 기다린 사람이 앞섭니다.
2. 추린 후보로 만들 수 있는 4명 조합에 **조합 점수**를 매겨 가장 높은 것을 씁니다.

```
조합 점수 = Σ개인 점수 − 중복(최근에 같이 친 짝) − 급수 불균형
                       − 나이 차 + 성별 정책 가산 − 3:1 감점
```

파일은 다섯 부분으로 나눠 뒀습니다: **1부 점수 · 2부 성별과 팀 · 3부 조합 탐색 ·
4부 배치 파이프라인 · 5부 시작과 종료.** 가중치는 설정 화면에서 바꿉니다.

### 잘림 문제

코트 카드가 flex로 눌리면서 아래쪽 두 자리가 통째로 잘려 나가던 문제를
고쳤습니다("4명인데 2명만 보인다"). 카드는 제 높이를 지키고 넘치면 컨테이너가
스크롤합니다. 폰에서는 빈 대기 슬롯이 한 줄로 접힙니다(드롭 자리로는 그대로 동작).

## 회원 명단 덮어쓰기 보호

회원 명단은 클럽의 원본 자산이라 한 번 날아가면 백업 파일 없이는 되돌릴 수 없습니다.
그래서 **명단을 통째로 바꾸는 조작은 관리 비밀번호를 받고**, 무엇이 어떻게 바뀌는지
먼저 보여 줍니다.

### 비밀번호를 묻는 조작

| 조작 | 위치 |
|---|---|
| 백업 파일 복원 | 회원 → 복원 |
| CSV 일괄등록 | 회원 → CSV 일괄등록 |
| 클라우드에서 다시 불러오기 | 설정 → 데이터 복구 |

확인 창에는 다음이 표시됩니다.

- 현재 클라우드에 몇 명이 있고, 덮어쓴 뒤 몇 명이 되는지
- **삭제되는 사람 / 추가되는 사람 / 정보만 바뀌는 사람**의 수와 이름
- 오늘 출석 중인 사람이 삭제 대상에 있으면 그 사실
- 지금 오프라인이면, 연결이 돌아오는 순간 이 내용이 클라우드에 그대로 올라간다는 경고

### 이 동작이 낳는 결과 (확인 창에도 그대로 적혀 있습니다)

- 클라우드의 회원 문서 `clubs/default/kv/members`가 **통째로 교체**됩니다. 지금 값은 남지 않습니다.
- 삭제된 회원은 DB에서 사라져 출석 목록·회원 화면·입장 화면에서 고를 수 없게 됩니다.
- 같은 클럽에 접속한 **모든 기기**에 그대로 반영됩니다. 이 기기에서만 되돌릴 수 있는 조작이 아닙니다.
- 대진판의 **되돌리기(↩)로는 되돌아가지 않습니다.** 되돌리려면 백업 파일이 있어야 합니다
  (확인 창의 **먼저 백업 내려받기** 버튼을 쓰세요).
- 지난 세션의 경기 기록 자체는 지워지지 않지만, 삭제된 회원은 기록에 이름으로만 남고
  회원 정보와의 연결이 끊깁니다.
- 복원(백업 파일)은 회원 명단뿐 아니라 **설정과 지난 세션 기록까지** 파일 내용으로 바뀝니다.

한 명씩 추가·수정·삭제하는 것은 지금처럼 비밀번호 없이 됩니다(삭제는 확인 창만 뜹니다).

### 자동으로 막히는 경우

비밀번호를 거치지 않았는데 회원이 사라지는 저장은 **아예 클라우드에 올라가지 않습니다.**
막히면 화면 위에 붉은 띠가 뜨고 그때부터 저장이 잠깁니다. 다음 두 가지가 대표적입니다.

- 명단을 제대로 못 불러와 화면이 빈 상태에서 아무 조작이나 한 경우
- 오프라인이라 클라우드 대신 이 기기 캐시가 "회원 없음"이라고 답한 경우
  (오프라인에 다녀오면 명단이 사라지던 원인이 바로 이것이었습니다. 이제는
  캐시가 답한 "없음"을 데이터 없음으로 받아들이지 않습니다.)

붉은 띠가 뜨면 **아무것도 조작하지 말고** 새로고침하거나
설정 → 데이터 복구 → 지금 다시 불러오기를 누르세요.

## 데이터가 비어 보일 때

새로고침이나 재배포 직후 회원 명단이 비어 보이면 **아무것도 조작하지 마세요.**
빈 상태가 클라우드로 올라가는 것은 위의 덮어쓰기 보호가 막아 주지만,
그 상태로 계속 쓰면 그날 조작이 저장되지 않습니다.

1. 화면 위에 붉은 띠(저장 잠금)가 떠 있으면 이미 저장이 잠긴 상태입니다. 새로고침하세요.
2. 띠가 없는데도 비어 있으면 **설정 → 데이터 복구 → 지금 다시 불러오기**를 누르세요.
   클라우드(Firestore) 원본을 그대로 다시 읽어 옵니다.
3. 그래도 안 되면 Firebase 콘솔 → Firestore → `clubs/default/kv/members` 문서를
   직접 확인하세요. 값이 있으면 데이터는 살아 있는 것입니다.

### 뷰어(게스트로 구경)는 대진판과 도움말만 봅니다

처음에는 회원 명단이 있는 탭(회원·출석)만 가렸는데 그것으로는 부족했습니다.
**기록** 탭에는 출석자 전원의 이름과 게임 수가 그대로 늘어서 있고, **설정** 탭에는
클럽 운영 값이 다 들어 있습니다. 그래서 뷰어에게는 대진판과 도움말만 남깁니다.

**도움말은 일부러 열어 뒀습니다.** 설명서에는 클럽 데이터가 한 줄도 없고,
처음 온 사람이 회원 등록하는 법을 읽어야 할 곳이 바로 거기라 가려서 얻는 것이
없습니다.

가리는 방식은 두 겹입니다.

1. `applyRole()`이 허용되지 않은 탭을 감춥니다.
2. `show()`가 허용되지 않은 화면 이름을 받으면 대진판으로 되돌립니다.
   `renderHist()`·`renderSet()` 안에도 같은 판정이 한 번 더 있습니다 —
   콘솔에서 직접 불러도 내용이 나오지 않게.

판정은 `gate.js`의 `allowedScreen(name)` 한 곳에서 합니다.

**대진판에 올라간 사람의 이름은 그대로 보입니다.** 지금 코트에서 부르는 이름이라
체육관에 서 있으면 어차피 들리는 것이고, 그것까지 가리면 대진판이 대진판이
아니게 됩니다. 가리는 것은 "등록된 회원 **전체** 명단"입니다.

뷰어는 설정 화면이 없으므로 역할을 바꿀 길이 막힙니다. 그래서 상단에
**입장하기** 버튼을 따로 내줍니다 — 이게 없으면 게스트로 한 번 들어온 기기는
localStorage를 지우기 전에는 영영 회원이 될 수 없습니다.

사용 설명서는 `<배포주소>/manual.html`로 앱 없이도 볼 수 있어, 아직 앱을 열지
않은 사람에게 링크로 먼저 보낼 수 있습니다.

회원은 입장할 때 출석 여부를 묻고, 이후에는 상단의 **출석하기 / 출석 중** 버튼으로
직접 바꿉니다. 코트에 배정된 뒤에는 본인도 빠질 수 없습니다(운영자에게 요청).

회원 로그인은 세션을 마감해도 유지됩니다. 다시 고르려면
설정 → **다시 입장하기**를 누르세요.

## 회원 입장 — 이름 가리기와 본인 확인

입장 화면의 회원 목록은 **이름의 마지막 글자를 가려서** 보여 줍니다
(김철수 → `김철○`). 본인 이름을 고른 뒤 **가려진 한 글자를 정확히 입력해야**
입장됩니다.

- 검색도 보이는 부분에만 걸립니다. 이름을 통째로 넣어 봐도 맞는지 확인해 주지 않습니다.
- 가린 이름이 겹치면(김철수·김철민 → 둘 다 `김철○`) 한 줄로 묶입니다.
  입력한 글자로 누구인지 갈리므로 본인 글자만 넣으면 됩니다.
- 두 글자 이름도 가려집니다(이수 → `이○`). 한 글자 이름은 가릴 것이 없어 그대로 보입니다.
- **3번 틀리면 3분 동안 잠깁니다.** 잠금은 그 기기에 저장되므로 새로고침해도 풀리지 않습니다.
  남은 시간이 화면에 표시되고 0이 되면 저절로 풀립니다.
- 한 번 입장한 회원은 다음부터 이 확인을 다시 거치지 않습니다.
  다시 고르려면 설정 → **다시 입장하기**.

**이건 인증이 아닙니다.** 명단은 여전히 브라우저 메모리와 Firestore에 그대로 있고,
익명 읽기가 열려 있는 한 마음먹은 사람은 읽을 수 있습니다. "지나가다 남의 이름을
보거나 눌러 보는 것"을 막는 장치입니다. 그리고 게스트 등록 화면에서 이미 있는
이름을 넣으면 "이미 있습니다"라고 알려 주므로, 이름을 하나씩 넣어 보며 확인하는 것은
여전히 가능합니다(중복 등록을 막으려면 어쩔 수 없습니다).
제대로 막으려면 실제 로그인(Google 등)과 역할 문서가 필요합니다.

## 동호회 개설 — 지금은 콘솔에서 손으로

자동 개설(신청 폼 + 서버)은 아직 없습니다. 새 동호회는 **콘솔에서 두 가지를
만들어** 열어 줍니다.

1. `clubs/{영문이름}/meta/club` 문서 생성

```json
{ "name": "한울배드민턴", "nameEn": "hanul", "region": "us",
  "plan": "promo", "status": "active",
  "promoUntil": 1760000000000, "createdAt": 1755000000000 }
```

2. `registry/clubs` 의 `count`를 **1 올립니다**

```json
{ "count": 4, "limit": 100 }
```

> **`count`를 올리는 것을 빠뜨리지 마세요.** 지금은 개설이 수동이라 상한을
> 지키는 주체가 사람입니다. Functions가 생기면 읽고-올리고-만들기를 한
> 트랜잭션으로 묶습니다. 보안 규칙은 문서 개수를 셀 수 없으므로,
> 규칙이 하는 일은 `registry/clubs`를 클라이언트가 못 고치게 막는 것까지입니다.

`meta/club`이 없는 주소는 규칙이 읽기·쓰기를 전부 거절하고, 앱은 "없는
주소입니다" 안내를 띄웁니다. 전체 상한은 **100개**입니다.

## 소유자와 운영자 — 비밀번호가 다릅니다

| | 소유자 | 운영자 |
|---|---|---|
| 경기 운영 (배치·시작·종료·정렬) | ○ | ○ |
| 설정 변경 · 세션 마감 | ○ | ○ |
| 회원 추가·수정·삭제 (한 명씩) | ○ | ○ |
| **회원 명단 통째 교체** (복원·CSV·다시 불러오기) | ○ | **✕** |

명단 통째 교체는 되돌릴 수 없고 모든 기기에 즉시 퍼지는, 이 앱에서 가장
파괴적인 조작이라 소유자에게만 둡니다.

**비밀번호를 따로 두는 것이 이 구분의 전부입니다.** 같은 값을 쓰면 화면만
다르고 권한은 같아서 "구분하는 척"이 됩니다. 저장 구조는 운영자 비밀번호와
완전히 같습니다 — `kv/ownerAuth`(salt) + `secret/ownerPin`(해시) + probe 대조.

소유자 비밀번호는 입장 화면의 **소유자**에서 정합니다. 아직 정하지 않은
동호회에서는 관리 비밀번호로 대신 확인하고 **그 사실을 알려 줍니다**(안 그러면
기존 동호회의 복원 기능이 통째로 막힙니다).

> **한계 — 규칙은 둘을 구분하지 못합니다.** 앱을 거치지 않고 Firestore를 직접
> 두드리면 운영자 비밀번호를 아는 사람도 명단을 갈아끼울 수 있습니다.
> 이 구분은 **앱 안에서만** 유효합니다. 규칙 수준의 구분에는 실제 로그인이
> 필요합니다.

## 운영자 비밀번호 — 저장하지 않고 확인만 합니다

예전에는 `settings.adminPin`에 `0116`이 **평문으로** 들어 있었습니다. settings 문서는
누구나 읽을 수 있으므로 그건 비밀번호가 아니라 공지사항이었습니다. 지금은 다릅니다.

### 어디에 무엇이 있나

| 경로 | 내용 | 읽기 |
|---|---|:---:|
| `clubs/{club}/kv/adminAuth` | `{salt, iter}` | **가능** — salt는 비밀이 아닙니다 |
| `clubs/{club}/secret/adminPin` | `{hash}` | **불가** — 규칙이 아예 막습니다 |
| `clubs/{club}/probe/{랜덤}` | `{hash}` | **불가** — 규칙이 대조만 해 줍니다 |

### 확인은 "읽어서 비교"가 아니라 "써 보고 되는지 본다"

앱이 입력값으로 PBKDF2-SHA256(21만 회) 해시를 만들어 `probe` 문서 생성을 시도하면,
규칙이 `secret/adminPin`의 해시와 대조해 **같을 때만** 통과시킵니다.

- 생성 성공 → 비밀번호가 맞다
- `permission-denied` → 틀렸다

비밀번호도 해시도 클라이언트로 내려오지 않습니다. 네트워크를 뜯어보든
`firebase-config.json`을 복사해 스크립트를 돌리든 **가져갈 것이 없습니다.**
얻을 수 있는 것은 맞다/틀리다 한 비트뿐입니다.

쓰기는 트랜잭션으로 합니다. 그냥 `setDoc`을 쓰면 오프라인 캐시가 서버에 닿기 전에
성공으로 답해서, 비행기 모드에서 아무 비밀번호나 통과합니다.

### 최초 설정

`kv/adminAuth`가 없으면 미설정 상태입니다. 운영자 입장을 누르면 **최초 비밀번호
설정** 화면이 뜨고, 두 문서를 한 번에 만듭니다. 규칙이 `!exists(kv/adminAuth)`를
강제하므로 **한 번 설정되면 앱에서는 절대 못 바꿉니다.**

예전 평문 PIN이 남아 있으면 그것부터 확인합니다. 새로 배포한 날 지나가던 사람이
운영자 자리를 차지하는 것을 막는 잠금입니다. 설정을 마치면 `adminPin`을 settings에서
지웁니다.

### 초기화 (잊어버렸을 때)

Firebase 콘솔에서 **`clubs/{club}/kv/adminAuth` 문서 하나만** 지우세요.
그 순간 미설정 상태로 돌아가고, 다음에 앱을 여는 사람이 새로 정하게 됩니다.

> ⚠ **지운 직후에는 먼저 여는 사람이 임자입니다.** 지웠으면 곧바로 본인이
> 설정하세요. 콘솔에서 지우고 커피 마시러 가면 안 됩니다.

`secret/adminPin` 문서는 지우지 않아도 됩니다 — 규칙이 `adminAuth`가 없는 동안에는
덮어쓰기를 허용하므로 새 값으로 갈립니다. (이 `update` 허용을 빠뜨렸다가 규칙
테스트에서 "초기화하면 영영 로그인 불가"가 잡혔습니다. 규칙만 눈으로 읽고
넘겼으면 그대로 나갔을 버그입니다.)

### 알고 쓸 것

- **첫 로그인은 인터넷이 되어야 합니다.** 확인을 서버가 하기 때문입니다. 한 번
  들어오면 역할이 기기에 저장되므로 그 뒤로는 오프라인에서도 운영자로 남습니다.
- **온라인 무차별 대입은 규칙으로 못 막습니다.** 콘솔에서 **App Check**를 켜고,
  네 자리 숫자 말고 8자 이상으로 정하세요. 앱도 8자 미만은 거부합니다.
- Firebase를 안 붙인 로컬 저장소 모드에서는 해시를 localStorage에 둡니다.
  서버가 없으면 "못 읽는 곳"이란 게 존재하지 않으므로, 그 모드에서는 보호가
  없다고 보는 편이 정확합니다.

## 회원 가입은 운영자 승인을 거칩니다

예전에는 게스트가 등록 화면에서 이름만 넣으면 곧바로 회원 명단에 올라갔습니다.
아무나 명단에 이름을 밀어 넣을 수 있었고, 그 이름이 입장 화면 목록에도 그대로
나왔습니다. 지금은 두 갈래입니다.

| | 흐름 |
|---|---|
| **승인 요청** (기본) | `kv/joinRequests`에 쌓입니다. 게스트는 뷰어로 대기하고, 운영자가 **회원** 탭의 `가입 요청 N` 버튼에서 승인합니다. 승인되는 순간 요청한 기기가 스스로 회원으로 전환됩니다(`members` 문서를 구독하고 있습니다). |
| **운영자 확인 후 바로 등록** | 운영자가 옆에 있을 때. 관리 비밀번호를 받고 즉시 등록합니다. |

승인 전까지 그 이름은 **회원 명단에도, 입장 화면에도, 출석 화면에도 없습니다.**
요청 문서를 members와 따로 둔 이유가 그것입니다.

동시에 두 사람이 요청하면 나중 것이 앞 것을 지울 수 있어서, 요청 목록의
읽고-고치고-쓰기는 트랜잭션으로 감쌌습니다.

## 여러 동호회

주소의 첫 조각이 동호회 식별자입니다 — `/` → `default`, `/hanul/` → `hanul`.
Firestore 경로와 로컬 저장 키가 통째로 갈라지고, 동호회마다 운영자 비밀번호가
따로입니다.

**자산 경로는 반드시 절대 경로여야 합니다**(`/js/...`, `/css/...`). 상대 경로면
`/hanul/js/store.js`를 찾는데 그런 파일이 없어서 호스팅 rewrite가 `index.html`을
돌려주고, 스크립트 자리에 HTML이 실려 앱이 조용히 죽습니다.

지금은 **아무 주소나 치면 그 이름의 빈 동호회가 생깁니다.** 등록부·소유권·요금제는
아직 없습니다. 전체 구조와 남은 단계는 **[`docs/multi-club.md`](docs/multi-club.md)**
에, 글로벌 확장·유료화까지 포함한 요구사항은
**[`docs/requirements.md`](docs/requirements.md)** 에 정리했습니다. 유료 멤버십은 서버(Cloud Functions)와 결제사 웹훅이 필요해
클라이언트만으로는 불가능하며, 같은 문서에 설계만 담았습니다.

## 운영 메모

- **운영자 동시 접속**: 최대 2명
- **자동 마감**: 첫 경기 시작 후 12시간
- **firebase-config.json**은 숨겨야 할 파일이 아닙니다. Firebase 웹 키는 원래
  브라우저에 노출되는 프로젝트 식별자라 저장소가 비공개여도 배포된 사이트에서
  그대로 보입니다. 실제 보안은 아래 Firestore 규칙이 담당합니다.

## Firestore 보안 규칙

규칙은 저장소의 **`firestore.rules`** 파일에 들어 있습니다. 내용과 이유는
그 파일의 주석에 적어 두었습니다.

> **적용 완료 (2026-08-14).** 콘솔에 붙여넣어 반영했습니다. 기한이 있던 테스트
> 모드 규칙은 더 이상 쓰지 않으므로 만료로 접근이 끊길 일도 없습니다.
> **`firestore.rules`를 고치면 다시 올려야 합니다** — 아래 배포 방법을 보세요.

### ⚠ 익명 로그인이 반드시 켜져 있어야 합니다

콘솔 → **Authentication → 로그인 방법 → 익명 → 사용 설정**.

규칙이 `request.auth != null`을 요구하므로, 익명 로그인이 꺼져 있으면
**앱이 클라우드를 아예 읽지 못합니다.** 예전 테스트 모드 규칙은 인증을 요구하지
않아서 이 문제가 드러나지 않았습니다.

이 상태가 되면 화면 위에 붉은 띠로 원인과 해결 방법이 그대로 뜨고, 저장은
잠깁니다(데이터는 안전합니다). 브라우저 콘솔에서 `__fb.auth.currentUser`가
`null`이면 익명 로그인이 안 된 것입니다.

급하게 운영해야 하는데 익명 로그인을 켤 수 없다면, 규칙의 `allow` 세 줄에서
`request.auth != null && ` 만 임시로 지우세요. 나머지 보호(전멸 차단·삭제 금지·
경로 제한·형식 검증)는 그대로 살아 있습니다. 임시 조치로만 쓰고 되돌리세요.

### 배포 방법 — 파일을 고치는 것만으로는 적용되지 않습니다

GitHub Actions 워크플로는 **호스팅만** 배포합니다. 규칙은 따로 올려야 합니다.

```bash
firebase deploy --only firestore:rules
```

또는 콘솔 → Firestore → 규칙에 파일 내용을 그대로 붙여넣으세요.

### 이 규칙이 막는 것 / 막지 못하는 것

**막는 것**

- `clubs/{club}/kv/` 밖의 경로에 쓰기
- 앱이 쓰지 않는 이름의 문서 만들기
- `{v, updatedAt}` 형식을 벗어나거나 900KB를 넘는 문서
- 문서 삭제 (앱은 어떤 문서도 지우지 않습니다)
- **회원 명단을 빈 값으로 덮어쓰기** — 앱 쪽 잠금이 뚫렸을 때의 마지막 방어선
- **운영자 비밀번호 해시 읽기** — 누구에게도, 어떤 경우에도 열리지 않습니다
- 설정된 비밀번호를 앱에서 바꾸거나 지우기 (초기화는 콘솔에서만)

**막지 못하는 것 (알고 쓰세요)**

- **회원 명단 읽기.** 익명 로그인을 켜 둔 이상 누구든 익명 계정을 만들 수
  있으므로 `request.auth != null`은 사실상 "인터넷 전체"와 같습니다.
  회원 이름·출생년도·급수가 공개돼도 괜찮은지가 판단 기준입니다.
- **운영자와 회원 구분.** 같은 이유입니다. 비밀번호를 아는 사람만 운영자가
  되지만, 규칙 입장에서는 여전히 "익명 사용자 아무개"라 회원 문서를 쓰는 것
  자체는 누구나 할 수 있습니다. 비밀번호는 **앱 화면을 잠그는 것**이지
  데이터베이스를 잠그는 것이 아닙니다.
- **비밀번호 무차별 대입.** `probe` 문서를 초당 수십 번 두드리는 것을 규칙으로는
  세지 못합니다. **App Check**로 막아야 합니다.

앞의 둘까지 막으려면 익명 로그인 대신 실제 로그인(Google 등)을 쓰고
`clubs/{club}/roles/{uid}`에 역할을 저장해 규칙에서 확인해야 합니다. 그때는
지금의 비밀번호 구조(`secret/adminPin` + `probe`)를 통째로 들어냅니다 —
익명 로그인 시대의 임시 방편이기 때문입니다. config 파일을 복사해
스크립트로 두드리는 경로는 **App Check**(콘솔에서 적용)로 막습니다.

`firebase-config.json`의 `apiKey`는 비밀이 아닙니다. 브라우저로 내려가는
프로젝트 식별자라 어차피 공개됩니다. 실제 보안은 위 규칙이 담당합니다.
